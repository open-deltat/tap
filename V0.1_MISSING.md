# TAP v0.1 - Missing Features

## ✅ COMPLETED (Core Infrastructure)

1. ✅ **Bitmap Allocator** - In-memory, per resource/day
2. ✅ **Concurrency Control** - Mutex per resource/day
3. ✅ **Horizon Limits** - Enforced in API
4. ✅ **Hold Expiry** - Background worker running
5. ✅ **Domain Schemas** - All entities defined (Tenant, Resource, Offer, Hold, Booking, LedgerEvent)
6. ✅ **Postgres Storage** - All tables created (tenants, resources, offers, bookings, holds, ledger_events)
7. ✅ **Event Sourcing** - Append-only ledger with replay
8. ✅ **Public API** - Availability and booking endpoints
9. ✅ **Private API** - All CRUD endpoints
10. ✅ **Error System** - Protocol-wide error codes
11. ✅ **Offer Integration** - Availability respects offers
12. ✅ **Booking Cancellation** - API endpoint exists
13. ✅ **Startup Replay** - State rebuilt from events

---

## ❌ MISSING (Critical for v0.1 Launch)

### 1. Auth & Security (HIGH PRIORITY)

**Missing:**
- ❌ JWT authentication for private endpoints
- ❌ Rate limiting (per-IP, per-tenant)
- ❌ Quotas/abuse guards:
  - `maxHoldsPerMinute`
  - `maxConcurrentHolds`
  - `maxBookingsPerMinute`
  - `maxBookingsPerIPPerDay` (public API)
- ❌ Idempotency-Key header support for POST endpoints

**Impact:** No security, vulnerable to abuse, can't prevent duplicate bookings

**Priority:** **MUST-HAVE** for production

---

### 2. Admin UI (MEDIUM PRIORITY)

**Missing:**
- ❌ Single-page admin app
- ❌ Sign in as tenant (email+password or magic link)
- ❌ Create/edit resources
- ❌ Set offers/opening hours
- ❌ Preview availability calendar
- ❌ View bookings with states
- ❌ "Connect Google Calendar" button

**Impact:** Can't manage resources/bookings via UI, must use API directly

**Priority:** **SHOULD-HAVE** for usability

---

### 3. Public Booking UI (HIGH PRIORITY)

**Missing:**
- ❌ Public route: `/:tenantSlug/:resourceSlug`
- ❌ Show resource name, timezone, basic info
- ❌ Query availability via public endpoint
- ❌ Click slot → booking form (name, email, phone)
- ❌ Submit → POST to public booking endpoint
- ❌ Payment integration (Stripe placeholder or paymentStatus='NONE')

**Impact:** Can't provide public booking links to customers

**Priority:** **MUST-HAVE** - This is the "90% of practical value" feature

---

### 4. Google Calendar Adapter (MEDIUM PRIORITY)

**Missing:**
- ❌ OAuth2 flow for Google Calendar
- ❌ Store refresh tokens
- ❌ Calendar selection per resource
- ❌ One-time import (GCal → TAP) for next 8-12 weeks
- ❌ One-way mirror (TAP → GCal) - create/update/delete events
- ❌ Retry logic for rate limits
- ❌ `syncStatus` tracking on bookings

**Impact:** Can't sync with Google Calendar, manual calendar management

**Priority:** **SHOULD-HAVE** for real-world usage

---

### 5. Enhanced Health/Status Endpoint (LOW PRIORITY)

**Missing:**
- ❌ `/status` endpoint (currently only `/health`)
- ❌ `dbStatus` check
- ❌ `last ledger_events.event_id per tenant`
- ❌ `buildId` from environment

**Impact:** Limited observability, harder to debug

**Priority:** **NICE-TO-HAVE**

---

### 6. Delta Streaming / SSE (COMPLETE ✅)

**Current State:**
- ✅ Cursor-based pagination (`GET /v1/events?cursor=&limit=`)
- ✅ Server-Sent Events (SSE) streaming
- ✅ Real-time event deltas
- ✅ `GET /v1/events/stream` endpoint
- ✅ Long-lived connection for real-time deltas
- ✅ Automatic reconnection logic (in client library)
- ✅ Heartbeat/keepalive messages
- ✅ `@tap/stream-client` package for easy consumption

**Status:** **COMPLETE** - SSE streaming fully implemented with client library

---

### 7. Payment Integration (MEDIUM PRIORITY)

**Missing:**
- ❌ Stripe integration (even placeholder)
- ❌ Payment webhook handling
- ❌ Update `paymentStatus` on bookings
- ❌ Store `paymentRef` and `paymentProvider`

**Impact:** Can't handle paid bookings, only free bookings work

**Priority:** **SHOULD-HAVE** if targeting paid services

---

## 📊 Priority Ranking (20% that gets 80% there)

### Must-Have for v0.1 Launch:
1. **Public Booking UI** - This is the core value proposition
2. **Basic Auth** - At least API keys or simple JWT for private endpoints
3. **Rate Limiting** - Prevent abuse on public endpoints
4. **Idempotency Keys** - Prevent duplicate bookings

### Should-Have for v0.1:
5. **Admin UI** - Makes it usable without API knowledge
6. **Google Calendar Adapter** - Real-world integration
7. **Payment Integration** - If targeting paid services

### Nice-to-Have (can defer):
8. Enhanced health endpoint
9. Advanced quotas/abuse guards
10. Full OAuth2 flow (can start with API keys)
